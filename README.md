# What Happened Here?

An AI observer for video. Upload a short clip and the system detects and tracks people and objects, turns their movements into a timeline of events, describes what happened in plain language, and answers your questions about it, by text or by voice.

> **Research question:** How can object detection, tracking, temporal modeling and Transformer / vision-language models be combined to turn raw video into a structured understanding of events and a natural-language description of what happened?

## How it works

```
Video
  → OpenCV            frame reading, fps, timestamps
  → YOLOv8n           people and objects, with confidence scores
  → BoT-SORT          persistent IDs across frames
  → Event extractor   enter / exit / place events as JSON
  → Qwen2-VL-2B       scene summary and question answering from keyframes
  → FastAPI           REST API
  → Streamlit         observation-console UI
```

Vision finds who, where and when; the language model explains what it means. The structured event log in between (`schema.py`) is the core design decision: it keeps the system debuggable, drives the event timeline, and serves as a template-based fallback summary if the VLM fails.

Voice is handled by faster-whisper (speech to text, on CPU) and gTTS (text to speech). Every detection run is logged to MLflow.

## Features

- Annotated video with bounding boxes and track IDs
- Timecoded event log (enter, exit, place)
- Natural-language summary generated by a vision-language model
- Question answering: "Who entered first?", "Did anyone leave an object?"
- Ask questions out loud and hear answers spoken back
- MLflow run tracking: thresholds, tracker, detection and unique-track counts, output artifacts
- Docker Compose setup with GPU support

## Requirements

- Python 3.10 or newer
- An NVIDIA GPU with about 8 GB of VRAM (developed on an RTX 4060); the VLM falls back to CPU but is very slow there
- [ffmpeg](https://ffmpeg.org/) on your PATH
- Internet access on first run to download models, and for gTTS

## Running locally

```bash
git clone https://github.com/Hasannlii0/what_happened_ai.git
cd what_happened_ai
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # macOS / Linux

pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
pip install -r requirements-api.txt -r requirements-ui.txt
```

Check that the GPU is visible:

```bash
python -c "import torch; print(torch.cuda.is_available())"
```

Start the API and the UI in two terminals, both from the project root:

```bash
uvicorn api.main:app --reload
```

```bash
streamlit run ui/app.py
```

Open http://localhost:8501, upload a video, then click **Analyze**.

The first analysis downloads YOLOv8n, Qwen2-VL-2B (about 4–5 GB) and the Whisper model, so it takes a while.

## Running with Docker

Requires Docker with NVIDIA GPU support (on Windows: Docker Desktop with the WSL 2 backend).

```bash
docker compose up --build
```

- UI: http://localhost:8501
- API docs: http://localhost:8000/docs

Hugging Face models are cached in a named volume, so they download only once. The API container can take a few minutes to start while Qwen2-VL loads; wait for `Uvicorn running on http://0.0.0.0:8000` in the logs before using the UI.

Use `--build` only after changing a Dockerfile or requirements file; otherwise `docker compose up` is enough.

## API

| Method | Endpoint | Description |
|---|---|---|
| POST | `/upload` | Upload a video (saved as `test_video.mp4`) |
| POST | `/analyze` | Run detection and tracking, extract events, generate the summary |
| POST | `/ask?question=...` | Answer a question about the analyzed video |
| POST | `/transcribe` | Convert an audio file to text |
| POST | `/speak?text=...` | Convert text to an mp3 file |

## Experiment tracking

Each run of `perception/detect_track.py` (including runs triggered by `/analyze`) logs to MLflow. To browse runs:

```bash
mlflow ui
```

Then open http://localhost:5000.

## Tips

- Use short clips (10–30 seconds) at 1080p or lower. Long 4K videos are slow and can crash the video writer.
- A static camera and good lighting give the most stable tracking.
- You can run the pipeline without the UI: `python perception/detect_track.py` reads `test_video.mp4` from the project root.

## Limitations

- Event rules only cover enter, exit and place.
- Tracker ID switches can still make one person appear as several.
- The VLM sees three keyframes, not continuous motion, so it can miss short actions.
- Analysis runs synchronously; long videos block the request.

## Future work

- LSTM or temporal Transformer for detecting action boundaries
- Learned action recognition (e.g. VideoMAE) for actions such as falling or picking up
- Route timing questions to the event log and visual questions to the VLM
- Anomaly detection and live camera mode
